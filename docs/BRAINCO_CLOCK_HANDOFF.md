# 强脑采集与时钟交接（2026-11-13）

供明洋及后续处理 Agent 使用。修改范围为“场景脑电实验程序-强脑版-uv”，旧版程序和已有数据未改写。

## 范式与运行

32 EEG 通道，默认 250 Hz、增益 6。全部 10 个场景、129 个物体、2 个视角，共 2580 张图片；每张默认重复 10 次，共 25800 次。固定种子 20261112，固定排程保留原试次编号，续采跳过已核验有效的项目。图片显示 0.6 秒，间隔 0.1 秒；每 80 张展示加减题 2 秒（无需作答），随后等待空格，0.8 秒后继续。休息不停止 EEG。图片部分约 301 分钟；总时长取决于人工休息，不保证恰好 7 小时。

项目使用 uv 管理根目录 `.venv`，Python 3.12，依赖锁在 uv.lock。运行安装环境.bat 后运行启动实验.bat。默认 main.py / RUNME.bat 仅运行 mock；正式入口为 `uv run --no-sync python main.py --config config/brainco.toml --gui`。连通性检查.bat 会产生测试数据，应与正式记录区分。配置路径相对于 TOML 所在目录。当前 s001 沿用用户指定编号，不是平台 8 位正式编号。

## 为什么发生漂移

原始适配器按第一次收包时间加“设备计数器差 / 标称采样率”生成样本时间。它假设设备和主机走速相同；偏差会累计，不能用等待更久修复。旧 Capture 还会将超过 10 秒的累计偏差认作时间戳错误。

marker-sample-clock-reference 提供接入思路和接口片段，没有提供可直接使用的完整时钟。当前 SDK 0.5.0 实测不导出 DeviceSampleClock、SoftSampleClock，ECapClient 未发现 clock/trigger 接口。本项目独立实现 SampleClock，不声称调用了这些 SDK 能力。

## 新标记路径

1. 在 TCP 接收端、乱序缓冲之前，记录当前最高设备样本计数器及 perf_counter 到达时间；保留原始网络分块以便完整重建。
2. 子进程将最新收包锚点随批数据传回。主进程以最近 120 秒锚点做线性拟合，启动至少预热 1 秒。
3. 屏幕事件先入队，必须等到其后的包已观测到；不允许向未来外推。拟合得到小数设备计数器，再映射到确实已保存的整数样本行。
4. 标记记录 effective_hz、ppm_vs_nominal、残差 RMS、锚点范围、数量及 generation。残差超过 50 ms 或速率偏差超过 2% 时拒绝正常映射；这些是工程保护阈值，不是实验精度验收标准。
5. 3 秒内不能完成映射就记录 marker_unresolved，不伪造有效标记；记录结束时未解决事件也保留。计数器重置不拼接为连续记录，重连必须另起记录。

**这仍是软件估计，不是硬 Trigger。** 101 表示图片开始、102 表示图片结束，图片身份由试次及事件元数据关联，不是把图片编号电气写入 EEG。标记 quality=software_estimated，hardware_sync_verified=false。sample_index 为连续文件 1-based 行号；设备 counter 是另一列，不能直接混用。导出 onset=(sample_index-1)/标称 Hz，表示文件采样网格位置，不表示经校准的主机真实秒。

包到达延迟、网络拥塞、屏幕刷新与软件回调延迟仍然存在。固定网络延迟与真实刺激到达时间无法单靠收包时钟分离；延迟缓慢变化也可能被拟合成漂移。该改动减轻标称速率导致的累计错位，不证明实际视觉事件已精确同步。硬件验证应比较光电探头/TTL 与 EEG 记录；当前链路没有实现该功能。

data/native 下每次记录的 .brainco 目录包含：

- continuous_eeg.sqlite3：整段 32 通道连续信号，包括图片、间隔、数学题、等空格的休息及结束前收到的数据；不按 trial 裁剪。chunks 中 eeg 为 float64，timestamps 为原先标称计数器时间，arrivals 为主进程接收时间，device 为计数器 JSON。
- wire_archives/<连接 UUID>/rx.bin：原始网络字节；chunks.jsonl 保存 offset、size、received，可重建分包、复查解码。metadata.json 与 summary.json 记录连接和结束诊断。
- wire_archives/<连接 UUID>-timing.jsonl：全程批次时序和 packet_anchor，不只保留内存末尾 2048 条诊断。
- events 表中的 marker_requested、aligned_marker、marker_unresolved、experiment_event、source_error；aligned_marker.clock_fit 是新拟合，nominal_sample_timestamp 保留旧映射值。
- 原有行为数据库/导出文件中的 trial、图像身份、固定 schedule、开始结束事件、有效性及中断状态；配置和代码/素材校验摘要随记录保存。

SQLite 使用 WAL、FULL synchronous 并约每秒提交。程序正常停止会关闭并核对收到/提交样本；断电或强杀仍可能丢失未落盘尾部，文件存在不代表完整。原始流和解码文件在同一磁盘，是可重建冗余，不是异地备份。设备无电/断网期间无法凭空保存 EEG，缺口必须显式保留。

正常停止还会生成按 sub-/ses-/run 组织的本地交接副本（native SQLite 和 CSV/JSON）。完整原始 .brainco 目录仍需一并交接，不能只拷贝派生 CSV。SDK 物理单位、参考和标定尚未确认，因此不伪造 EDF/BDF，eegqc_ready=false。

## 给明洋的处理建议

brainco-clock-drift-20261109 包提出两类路线：有可信样本索引时按样本网格定位；缺乏可信同步时按单段 EEG 诱发反应估计 offset 与漂移，并做独立验证。其历史 ppm 分布和分数阈值不是本批数据的测量结果，不应直接套用；其中脚本还包含原作者的绝对路径和特定输入格式。

优先按每次连续连接分别重建计数器、核查缺口、用完整收包锚点复拟合，并比较新旧标记位置。绝不能把旧版“主机时间乘标称率”得到的 sample_index 当作硬件真值。必要时再做 EEG 反应模板校正，保留原始标签、拟合参数、独立验证分割与派生版本；不要覆盖原文件。没有真实传感器同步时，算法修正结果仍需报告不确定度。
